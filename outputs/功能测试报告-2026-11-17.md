**已修复的启动问题。** 工作台曾把任何监听错误都显示成“端口已被占用”。现在只有 `EADDRINUSE` 这样报告，`EPERM` 和 `EACCES` 提示环境不允许监听或连接，并保留原始原因。已在本机复现并验证真实拒绝路径；桌面探测与启动回归另验证未知服务仍被拒绝。配对页面测试现在使用已经安装的完整 Chromium，也接受 `CHROMIUM_PATH`，不再依赖单独的 Headless Shell。

**已修复的发行包问题。** 原 0.4.0 包缺少当前回复复制图标及样式。当前安装包为 [navi-ui-0.4.1.tgz](navi-ui-0.4.1.tgz)。`ui:pack` 在替换文件前校验条目名称和内容；`ui:check` 同时检查两处应用副本与已经存在的当前版本安装包。已复现过期包被拒绝、重新打包后通过。

**本轮夹具补测。** Node 原生 WebSocket 客户端与进程内协议对端实际交换 HTTP 升级数据：101 握手成功、403 拒绝、对端不回应三种情况均符合预期；180 毫秒超时设置实测约 187 毫秒。浏览器 CLI 用模拟页面适配器执行正式用例流程：五步成功、断言失败后停止、拒绝跨来源、Runner 退出 0 时仍保留失败结果，四项均通过。逐项比对了落盘 JSON 与工作台解析结果、输出中的 JPEG 与磁盘字节；JPEG 是固定夹具，本次没有通过该适配器生成真实截图。

**为何标准回归仍有 65 项未通过。** 62 项直接报告 `EPERM`，另 3 项浏览器断言依赖未能启动的内置页面服务。57 项 HTTP 用例用内存字节流补测通过，余下的 8 个原用例需要实际系统行为：端口占用和释放、挂起的 WebSocket、团队网站真实启动登录和端口占用，以及 4 个 Chromium 执行器场景。独立的扩展浏览器脚本和工作台配对授权页不在 559 项内；当前测试配置没有加载 Navi Link，启动独立 Chrome 的原生侧栏脚本仍受系统权限限制。
