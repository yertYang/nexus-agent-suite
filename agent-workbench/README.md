# Navi

[下载 macOS 桌面工作台 ZIP](https://github.com/yertYang/nexus-agent-suite/raw/refs/heads/main/downloads/navi-desktop-macos.zip)。完整解压后打开 `Navi.app`，保留同目录的 `agent-workbench/`。支持 Intel 和 Apple 芯片、macOS 12+，需要 Node.js 24+、Corepack，首次启动需联网。启动器未经 Apple 公证。

Navi 把模型对话和本机项目连在一起。你可以授权一个目录，在聊天里看模型提出的工具调用，批准需要写入或执行命令的操作，然后核对结果。无需安装 Codex。

- **API 模式**：Navi → Codex Proxy RS（CPR）的 Responses 接口 → 模型 → Navi 根据原生工具调用驱动 Nexus → 本地 Runner。
- **Chrome 侧栏聊天**：Navi Link 可独立配置模型 API，聊天、操作网页，并读取通过浏览器选中的本地目录。可在确认改动后修改已有文本。需要 Finder、新建文件或项目用例测试时，可切换到本机模式，复用工作台已保存的模型 API，配对时按需勾选「允许运行测试」「允许浏览器操作」「允许本机文件操作」。每次工具操作仍须确认。
- **网页账号模式**：也可以用你自己的 ChatGPT 或 DeepSeek 网页账号。扩展与工作台确认项目后直接连接 Nexus，不需要为网页模式填写模型 API URL 或 Key。每次工具请求仍须在扩展中确认。

## 多人团队网站

在本目录用 `npm run team:init -- admin` 创建管理员，再用 `npm run team:start` 启动独立网站（默认 `http://127.0.0.1:17890`）。支持管理员管理成员密码与状态、账号隔离的对话、绑定插件、绑定个人电脑处理目录任务，以及在「任务文件」按用户名共享、撤销或替换带版本号的文件。默认不共享，成员不能使用管理员部署接口。服务器模型配置和本机工具凭据分开管理。「目录任务」仅在有在线设备获准新建文件时加载任务文件作为内容来源；只有只读设备时仍可列目录和读取文本。详见[团队网站操作手册及验收范围](docs/TEAM_SITE.md)。使用 Linux 容器部署时，见[部署包安装、更新与恢复](docs/SERVER_RELEASE.md)。下文描述本机工作台。

Linux 服务器可按[发布与更新手册](docs/SERVER_RELEASE.md)部署团队网站。在发布包目录运行 `sudo bash install.sh`，会同时安装网站和主机部署服务。就绪检查通过后，网站管理员在「部署管理」点击「一键部署」，由主机按私有配置拉取 Docker 镜像或 GitHub Release，并通过 `deploy/team/update.sh` 停服备份、按镜像摘要更新和检查就绪状态。页面展示进度和最近一次结果，服务器连接信息和更新来源在主机维护。需要恢复时，在原安装目录运行 `sudo ./update.sh --restore backups/备份名`；脚本先检查备份副本，再用对应镜像和数据启动，保留切换前的现场。模型 Key 和站点配置不随镜像替换。

## 在 macOS 打开 Navi

桌面工作台升级后，请先结束进行中的任务，在 Finder 双击套件根目录的[重启 Navi.command](../重启%20Navi.command)。它会核对端口、用户和启动脚本，正常停止当前套件的桌面工作台，再打开 Navi。重启后旧配对失效，需从扩展重新连接。

保留套件目录结构，在 Finder 双击套件根目录的 **Navi.app**。首次启动会准备本机 Nexus 和 Runner，随后打开浏览器登录；再次双击会打开已运行的工作台。直接访问工作台时，在「欢迎使用 Navi」输入本机操作员密钥。保存有效的 URL 和 Key 后，普通对话即可处理本机项目和网址测试。网关错误消息会隐藏其中的完整 Client Key；含该密钥的错误码会替换为通用错误码。无效 JSON 只显示格式错误，不显示原文。

首次准备需要 Node.js 24+、Corepack、Git 或系统 tar，并且要能下载固定的依赖。Nexus 的原生 SQLite 依赖可能需要 Python 3 和 C++ 编译工具。仅在使用套件自带的 CPR 网关或隔离浏览器时需要 Docker Desktop。

从尚未支持 Office 读取的版本升级时，请先停止旧工作台，再双击新版 **Navi.app**。启动器发现本机 Runner 缺少当前 Office 适配时，会先准备锁定的 Nexus 组件再启动；如果工作台已经运行，双击只会打开现有实例。手动启动的用户请先停止旧进程，再运行 `npm run prepare:nexus` 后启动。

## 模型连接

1. 在「连接设置」填写 API Base URL 和 API Key。使用本机 CPR 时，默认地址为 `http://127.0.0.1:8080/v1`，Key 为 CPR 签发的 Client Key。远程网关使用 HTTPS。
2. 点「保存并连接」。Navi 验证当前 Key 能读取模型目录后保存连接，并在输入区右下角更新模型选项。验证失败会保留原配置，同时在表单内显示原因和未保存的输入。未保存的输入可在当前页面会话内跨菜单保留；重新载入网页或退出会清除。页面不会回显已保存的 Key；更换网关地址时请重新填写对应 Key。
3. 如果需要配置本机 CPR 的上游账号或签发 Client Key，可独立访问其[原版管理端](http://127.0.0.1:8080/)。上游账号和 Key 的额度由网关管理。若已通过别的方式配置好兼容的网关，Navi 只需要其 URL 和 Key。

同一对话的后续消息带有同一个会话标识，每条用户消息保留自己从服务器记录的 UTC 时间；工具调用期间保留当前消息的轮次标识。CPR 可以按其位置策略对齐请求中的时区和结构化搜索位置。公网出口由实际网络或网关代理决定。

## 操作本机项目

在「项目与权限」注册本机文件夹，再在对话中选择项目和模型。注册的新目录只读且不开启命令。配置好模型后，可以用工作台私有的示例目录试「读取 README.md」，需要写入或执行时再调整对应项目的权限。在对话中核对每次写入或命令请求，批准后才会交给 Runner。

你的消息显示在右侧气泡中，Navi 的回复在左侧按正文排版，支持标题、列表、引用、表格和代码块。点「复制回复」可复制原始 Markdown，点「复制代码」只复制该段代码；宽表格和长代码行可横向滚动。

对话顶部可以选择项目，输入区右下角可以选择模型。用 Tab 移到模型选择器时，浅色背景和下划线表示焦点。

在输入区右下角点停止会停止后续调用。已经发到 Runner 的同步操作可能继续完成；界面会标为「执行状态未知」。核实结果后再决定是否重试。

## 在对话中运行测试用例

1. 在工作台对话选定项目，或打开已授权运行测试的 Navi Link 侧栏。例如发送：**请在 https://example.com/ 运行 `tests/cases` 目录里的测试用例。** 在同一条消息里提供相对目录和唯一的完整 HTTP(S) 网址，再确认目录。
2. 对于 Markdown、Excel 和 Word 用例，Navi 从所选项目读取行、单元格或段落，先观察目标页面，再提出可核对的浏览器步骤。核准后由工作台内置的隔离 Chromium 执行；模型无需选择另一个项目或提供命令。同一计划的浏览器导航限定在该网址的来源内。Office 文件需要套件当前版本的 Nexus Runner；浏览器依赖可由兼容的本机浏览器或 Docker Desktop 提供。
3. 对于已有 Playwright 或 Selenium 脚本，来源项目须启用读写和项目命令权限，且项目已安装相应依赖。选定脚本须接受 `--url`；Playwright Test 的现有项目启动器还须接受 `--case`，此模式从已授权项目根目录发现用例。Navi 展示完整命令供确认。一次可选择一组文档或一个已有脚本；有多组来源时可分次运行。
4. 查看实际步骤、断言、状态和可用截图。脚本必须提供与本次目标对应的通过证据；只有退出码或观察结果时不会标记通过。原脚本可能自行创建浏览器或访问其他站点，不能将文档计划的同源限制视为原脚本的隔离保证。如果 Nexus 还要求审批，完成后 Navi 会再次核对来源和命令才继续。

## 连接独立网页助手

1. 在运行 Navi 的同一台电脑、同一个 Chrome 浏览器内打开「Navi Link」侧栏，在设置的「连接方式」中选「使用本机 Navi」，点「连接 Navi」。工作台会打开确认页；如果尚未登录，请先登录。
2. 选择一个已经授权并启用的项目。如果要在侧栏运行测试，勾选「允许运行测试」；要打开网页或搜索，勾选「允许浏览器操作」；要打开本机目录、创建或修改文件，勾选「允许本机文件操作」，然后点「连接」。回到侧栏查看连接结果。如果已在工作台保存模型 API，就可以选择模型、发送消息；侧栏模型选择在输入区，顶部不预选项目，文件任务在对话中选择当前连接已授权项目后继续；日常配对无需复制令牌或填写项目 ID。
3. 默认侧栏工具只读。启用操作授权后，浏览器工具通过扩展执行，文件写入仍要求所选项目读写权限，测试使用独立的受限操作及审批。侧栏聊天连接有效期 12 小时；工作台重启或连接到期后须重新配对。网页账号模式的 Nexus 令牌有效期 7 天。配对请求须在 2 分钟内批准；超时、验证失败或要换项目时，从扩展重新发起。

网页账号模式需要手动连接时，可展开工作台「网页扩展」里的「高级：手动连接」，签发独立令牌，再到扩展高级设置输入令牌和项目 ID。手动 MCP 连接不能启用本机模式侧栏聊天；本机模式请配对。独立聊天不需要配对。操作员密钥、CPR Client Key 和 Nexus 管理密钥都不能填给扩展。

两项操作权限默认关闭、分别校验。浏览器权限不开放 Finder 和文件写入，文件操作权限不开放日常浏览器工具；未勾选文件操作仍保留项目只读工具。历史合并授权按原范围兼容，缩小范围需重新配对。部署本次后端变更后须重启工作台，随后刷新授权页并重新加载扩展，才能使用拆分选项。

## 从 Navi Link 操作真实浏览器与目录

使用扩展独立模式可操作网页、读取本地目录和修改已有文本，目录由浏览器选择和授权。以下说明适用于需要项目工具或复用工作台模型的本机模式。[扩展使用说明](../browser-extension/README.md)

在配对页按需独立勾选「允许浏览器操作」和「允许本机文件操作」，保持侧栏打开，即可发送“用 Chrome 打开百度搜索苹果”“读取刚才的页面”“在 Finder 打开当前项目目录”。新对话默认不启用本地文件工具，网页操作可以直接开始；目录、文件或项目测试请求先显示对话中的项目选择卡，选择后继续原请求。简单的“打开百度网站搜索苹果”只提出一次浏览器搜索，批准后直接打开结果页，不读取内容。其他网页或文件任务仍按实际操作确认。扩展侧栏默认隐藏操作流水，点击该轮的记录图标可查看具体调用。发送和停止使用上箭头与方块图标。即使项目的执行模式为禁用，打开网页和目录也可使用；无需为它们启用项目命令。

`navi_browser` 由配对的扩展后台领取一次性任务，调用 Chrome/Edge 标签页和隔离脚本 API；提供打开、百度搜索、页面读取、普通输入框填写和点击。读取/交互需浏览器授予该网站访问权限，只控制当前连接创建的标签页。`navi_open_directory` 从当前安装的 Runner 登记表核对项目，解析真实目录并在 macOS Finder 打开；拒绝目录越界、跨 Runner 和文件路径。文件创建、修改和建目录仍通过 Nexus MCP，并逐次审批，不开放任意命令工具。

旧配对不会自动升级权限。升级代码后需停止旧 Navi、重新启动，并重新加载和配对扩展。目录打开目前仅支持 macOS；尚未实现整桌面 Computer Use。浏览器任务等待扩展最多 90 秒，扩展中断不会自动重放操作；已发出的副作用无法由“停止”撤销。流程详情见 [Navi Link](../browser-extension/README.md)。

## 部署管理

在侧栏打开「部署管理」，可通过本机 SSH 更新**一个已部署的 Linux Docker Compose 应用**，并打开已有 1Panel 或其他管理面板。无需配置模型 API；工作台继续只监听本机，不作为公网管理后台。

1. 在本机 `~/.ssh/config` 配好服务器 Host 别名、用户、端口和密钥，并提前通过 SSH 确认主机指纹。连接必须能免交互登录；页面不收集 SSH 密码或私钥。服务器需要 Docker Compose v2（支持 `pull --policy` 和 `up --wait`）、Linux `flock`，SSH 用户需要应用目录写权限及 Docker 权限。私有镜像仓库需在服务器预先登录。
2. 旧版已保存的部署目标可继续使用。首次配置或更换目标时，在本项目的 `.runtime/private/deployment-target.json` 中填写下方的 JSON（文件权限设为 `0600`），然后重启工作台。每次只管理一个应用和一个 Compose 文件；项目名必须与已有容器一致。
3. 在页面点「检查状态」。确认当前目标已有容器后，才可更新或重启。页面显示服务、镜像、运行和健康状态；连接参数不出现在表单、操作记录或确认弹窗中。
4. 点「一键更新」并确认。后端依次检查配置、拉取镜像、执行 `docker compose up -d --no-build --pull never --wait --wait-timeout 120`，再读取容器状态。拉取失败时不执行重建。不会运行 `down` 或删除数据卷；应用自身的数据库迁移仍可能修改数据。没有 healthcheck 的服务仅等待运行，不等同于业务验收通过。
5. 「重启应用」执行 `docker compose restart --timeout 30` 后读取状态，不拉取新镜像、不等待业务健康。「打开管理面板」在新标签打开已保存地址，面板独立登录；网站、证书、文件和备份等操作由该面板提供。

本机配置示例（替换为自己的目标，`panelUrl` 可省略）：

```json
{
  "name": "示例应用",
  "sshHost": "example-host",
  "directory": "/opt/example",
  "project": "example",
  "composeFile": "compose.yaml",
  "panelUrl": "https://panel.example.com"
}
```

更新使用服务器当前 Compose 文件指定的镜像。固定版本标签或 digest 不会自动切换到新版本；更换版本需先在服务器或管理面板修改配置。当前不提供镜像版本选择、源码构建、自动备份或回滚、Docker 引擎升级、1Panel 安装或任意远程命令。请在更新有状态应用前自行安排备份。

任务离开页面后继续执行，界面轮询显示进度；本机等待上限为 10 分钟。服务器应用目录内的 `.navi-deploy-<项目名>.lock` 防止 Navi 同时执行冲突操作。请求编号在最近 20 条记录内去重。SSH 中断、等待超时或工作台重启后的未完成更新会标记「结果未知」，不会自动重放；先点「检查状态」，重新取得同一服务器锁并读取状态后才允许继续。原操作保持未确认，不会改写为成功。该锁不阻止你从终端或其他面板执行操作，维护期间请避免同时修改同一应用。

已生效的目标和最近 20 条操作记录保存在 `.runtime/private/deployments.json`（文件权限 0600）。仅记录阶段、固定错误说明和必要容器状态，不保留 Docker 原始输出、环境变量、应用日志或 SSH 私钥。完整模拟模式不加载本机部署目标，禁止连接服务器；本机工作台中的部署操作使用真实 SSH，与模型是否模拟无关。

部署管理的自动化验证使用合成 SSH/Docker 返回值和真实本地 shell，不代表真实服务器已更新；当前真实 SSH、Docker Compose 和浏览器界面尚待环境允许后验收，详见[验收记录](docs/VALIDATION.md)。

## 开发与手动启动

登录、设置、项目、审批、会话、对话测试和网页扩展配对共用 Navi UI 组件。工作台和 Navi Link 使用 Navi UI 的 Element UI 风格浅色主题：蓝色主操作、4px 控件圆角和轻边框。共享回复渲染器支持可选的复制图标；工作台沿用文字复制按钮。扩展复用基础组件，并以局部样式提供圆角输入区、28px 操作图标、深色发送按钮和设置弹窗；工作台保留原有布局。主操作用蓝色按钮，项目与模型选择器的文字与箭头垂直居中，在窄屏会截断长名称，展开后可查看完整选项。桌面侧栏底部将模式、刷新、退出和收起按钮放在一排；折叠为图标栏后纵向排列。设计源在套件的 `design-system/navi-ui/`，工作台独立使用 `public/ui/` 的副本。`npm run ui:check` 验证副本的文件与版本清单一致。

手动启动工作台时，在本目录运行：

```sh
npm run prepare:nexus
npm run cpr:up    # 使用套件自带的 CPR 时
npm start
```

直接访问 [工作台](http://127.0.0.1:17880) 时，开发者可运行 `npm run --silent operator` 取得操作员密钥。`npm run model-demo` 使用模拟模型和真实 Nexus、Runner；`npm run demo` 只预览界面和内存模拟工具。真实网关调用失败后不会改用模拟模型。

启动时，端口已被占用与系统禁止连接／监听会显示不同原因。出现 `EPERM` 或 `EACCES` 时，请在允许本机回环网络的环境启动。

浏览器直接打开时，在「欢迎使用 Navi」输入本机操作员密钥。日常使用可从 Finder 双击 Navi.app 自动登录。

`npm run prepare:browser` 安装锁定的 Playwright，`npm run browser:up` 和 `npm run browser:down` 控制隔离浏览器。可通过 `npm run import-key < /path/to/client-key-file` 从权限为 0600 的本地文件导入 Client Key。手动启动的工作台可用 Ctrl+C 停止；启动器只清理自己启动的服务。`npm run cpr:down` 单独停止 CPR，保留数据卷。

详见 [套件架构](../ARCHITECTURE.md) 和 [验收记录](docs/VALIDATION.md)。代码上游版本、下载地址和散列见 [vendor/LOCK.json](vendor/LOCK.json)。本工作台使用 AGPL-3.0-only；Nexus 使用 AGPL-3.0-only，CPR 使用 Apache-2.0。原许可在 [vendor/licenses](vendor/licenses) 和源码归档中。

操作员的近期对话和截图保留在当前服务进程。停止工作台以后，这些临时运行记录会清除；Nexus 自行管理的项目和工作流存于其运行数据目录。
