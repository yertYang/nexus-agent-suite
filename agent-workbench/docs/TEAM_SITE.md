# 启动和使用 Navi 团队网站

团队网站是独立的 Node.js 24+ 入口。网站负责账号、成员自己的对话、设备任务和按账号共享的文件；本机工作台继续负责本机目录和 Runner。网站不需要安装扩展、Nexus 或 Docker 才能登录。**不要将本机操作员服务 17880 或 MCP 服务 18080 代理到公网。**

Linux 生产环境从 GitHub 拉取指定版本、备份、更新与恢复见[服务器发布手册](SERVER_RELEASE.md)。下列 Node.js 命令也适用于独立运行或本地开发。

## 初始化并启动

在 `agent-workbench` 目录执行：

```sh
npm run team:init -- admin
npm run team:start
```

第一条命令只在空账号库中创建首个管理员，在终端隐式输入密码（至少 12 个字符）。不要将密码放在命令行。浏览器访问 `http://127.0.0.1:17890`。管理员在「成员管理」创建成员和临时密码，成员首次登录先改密。网站不开放注册。重置密码或停用账号撤销此账号的会话、配对码及插件/设备连接。启用不会恢复旧凭据。网站账号不同于本机操作员、模型提供商或 ChatGPT 网页账号。

服务器部署时，在服务器上运行同一入口，设置 `NAVI_TEAM_ORIGIN=https://你的域名`，让 HTTPS 反向代理保留原始 `Host`、转发到 `127.0.0.1:17890`。程序仅监听环回，域名、协议和外部非标准端口必须与 `NAVI_TEAM_ORIGIN` 完全匹配。代理须允许至少 2 MiB 文件请求和超过 95 秒的模型响应等待。生产使用专用服务账号和数据目录，不与本机工作台共用私有文件。

| 配置 | 用途 |
| --- | --- |
| `NAVI_TEAM_ORIGIN`、`NAVI_TEAM_PORT` | 网站外部根地址和环回监听端口。默认分别为 `http://127.0.0.1:17890` 和 `17890` |
| `NAVI_TEAM_DATA` | **专用**持久化目录，初始化与启动须一致；默认 `.runtime/team`。目录权限 0700，含账号、会话哈希、成员消息、共享文件、任务与部署记录。不要指向现有用户主目录或公共目录 |
| `NAVI_TEAM_API_URL`、`NAVI_TEAM_MODEL`、`NAVI_TEAM_KEY_FILE` | 配置聊天时三项同时提供：Responses 兼容的 `/v1` 根地址、实际模型 ID、服务账号可读的私有 Key 文件（0600）。变更后重启。未配置时可登录、管理账号、共享文件和运行目录任务，聊天不会使用模拟模型兜底 |

使用单个服务实例和本机 SQLite 文件系统。备份时停止实例，再完整复制专用数据目录（含可能存在的 SQLite WAL 文件）。恢复应先在隔离环境验证；数据库含文件正文和对话，使用受保护的磁盘与备份存储。本版未实测生产备份恢复、多副本或高可用部署。

## 任务文件：指定成员共享

1. 打开「任务文件」并上传。新文件仅自己可见，即使是网站管理员也不会通过文件接口自动获得访问权。支持文本及二进制文件，单文件最大 2 MiB，每位所有者最多 300 个文件、共 64 MiB。
2. 展开文件，输入接收方的用户名，选择「只读」或「可编辑」。对方刷新「任务文件」，在「共享给我」中看到该文件并下载。可编辑成员还能替换内容；只有所有者能改共享权限、撤销共享或删除文件。
3. 替换时检查页面所见版本；有人先更新时会拒绝过时版本，重新下载、合并再上传。版本号用于防止覆盖，**本版不保存可回滚的旧版文件**。
4. 在「目录任务」中把已完成的任务结果保存成私有文件，再按需分享。在有新建权限的本机项目上，可选择自己有权读取的 UTF-8 任务文件作为新文件内容（最多 12000 字符）。提交任务时验证文件权限与版本，复制当时的文本；接收方仍需在自己的电脑批准写入。

共享文件不会共享原目录、设备、对话或审批权。撤销后禁止继续下载或替换；已经下载的副本或已提交任务中的内容不会被追溯删除。二进制文件可共享下载，不会当作文本写入设备或自动发送给模型。

## 网站与插件聊天

「我的对话」与 Navi Link 的团队页面共用当前账号的会话，可继续此前的对话。团队模型配置在服务器，扩展不接收模型 Key。聊天只发送该对话的历史与当前消息，不会自动执行网页或目录操作。

在已加载新版的 Navi Link 侧栏，打开设置 →「团队网站 · 账号对话」，填入网站根地址并打开网站。登录后在「我的连接」点「连接 Navi Link」，将 2 分钟有效的一次性配对码填回插件，按需授予该域名的访问权限。插件连接最多 7 天；浏览器会话结束后需要重新绑定。在网站撤销连接会立即阻止后续请求。请勿把配对码或密码交给他人。

## 本机设备与目录任务

1. 在**目录所在的电脑**启动本机 Navi 和 Nexus，在「项目与权限」登记所需项目。团队站点仅接收设备名、项目显示名和经批准的任务结果，不接收 SSH 凭据、本机 MCP 令牌或真实目录路径。
2. 在这台电脑的 `agent-workbench` 目录运行 `npm run team:device -- https://你的域名` 查看可选项目及 ID；再运行 `npm run team:device -- https://你的域名 项目ID`。如确需创建文件，先把对应本机项目设为可读写，再追加 `--allow-create`。
3. 网站「我的连接」→「连接本机目录」生成设备专用配对码，在本机终端提示符输入。每个执行端进程仅绑定一个账号和一个已登记项目。保持终端运行；主动正常退出会撤销连接，下次启动需重新配对。
4. 网站「目录任务」选择在线设备，填写项目内相对路径，发起列目录、读文本或新建文件。在本机确认目标、操作和新文件内容，输入 `yes` 才执行。文件读取最多前 120 行，回传文本最多 14000 字符。Nexus 若要求额外审批，本版不自动完成额外审批；会报告未执行。没有覆盖、删除文件或任意命令功能。
5. 任务列表可刷新。设备离线时不接受新任务；未领取任务 2 分钟过期，已领取任务 5 分钟未获确认则标记结果未知。离线、中断或丢失回执后不自动重放操作。

## 服务器部署管理

主机启用部署服务后，网站管理员可在「部署管理」点击「一键部署」更新当前团队网站。主机按运维人员私下配置的 Docker 镜像或 GitHub Release 拉取更新。页面显示进度与最近一次结果，管理员账号的操作记录会登记提交编号。部署配置、连接信息、镜像地址和主机日志由运维人员在主机维护。启用方式及恢复步骤见[服务器发布手册](SERVER_RELEASE.md#启用团队网站一键部署)。旧版团队网站保存的 SSH 目标已退出网站部署流程。

## 验证范围

团队网站的历史验收使用实际 SQLite、加盐 scrypt、正式请求处理器、文件字节与进程逻辑；模型和 Nexus 使用夹具。测试覆盖成员隔离、登录撤销、插件凭据范围、设备任务归属、共享文件的读写/撤销、并发版本冲突以及任务结果导出。真实多人 HTTPS、Chrome 配对、线上模型和两台真实电脑的目录联调仍需部署环境验收。一键部署的验证范围见[验收记录](VALIDATION.md)。
