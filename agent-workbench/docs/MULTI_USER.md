# 多人共用 Navi：产品目标与迁移方案

状态：共享网站、账号、插件对话、本机设备任务和按账号共享任务文件已在仓库实现。操作步骤和当前验证边界见[团队网站手册](TEAM_SITE.md)。以下是各阶段的产品目标；真实线上联调与发布尚未验收。目标是所有人访问同一个 HTTPS 网站，每人使用自己的 Navi 账号和密码登录。管理员负责账号，成员自行连接浏览器插件和自己的电脑。现有本机工作台、Navi Link 独立模式仍可单独运行。

## 登录后如何使用

| 想做什么 | 操作 | 在哪里执行 |
| --- | --- | --- |
| 管理成员 | 管理员创建或停用账号、发起密码重置；成员设置自己的新密码 | 共享网站。密码仅保存加盐哈希，管理员不能查看原密码 |
| 用插件对话 | 用户在 Navi Link 点「连接团队网站」，在已登录的网站确认账号和浏览器，回到侧栏直接对话 | 网站调用模型并将会话归入该账号。普通聊天不要求安装本机执行端、选择目录或授予网页操作权限 |
| 使用本地目录 | 用户在自己电脑上的 Navi 执行端绑定账号，选择一个文件夹；网站或侧栏选择「我的设备 → 项目」发起任务 | 执行端访问授权目录并返回任务所需结果。电脑离线就显示离线，不在服务器上按同名路径执行 |
| 更新服务器应用 | 获授权的管理员进入「部署管理」，检查目标后更新或重启 | 管理员专用的运维连接。普通成员、插件和模型均没有服务器部署权限 |

例如，小李只用插件聊天时，无须启动本地工作台。要修改自己电脑上的项目时，再打开本机执行端并授权该项目。小王即使登录同一个网站，也不能列出小李的目录、打开他的对话或替他批准一次写入。

文件可由所有者显式共享给指定账号（只读或编辑），与目录和设备权限分开。

## 三处需要区分的权限

- **网站账号**负责身份和资源归属。第一版按管理员、成员两种角色设计，暂不开放自助注册。对话、设备、项目、任务、审批和产物都关联用户；列表、详情、下载、事件流和写接口均在服务端验证归属。管理员管理账号的权限不自动赋予成员的对话或目录访问权。
- **插件连接**只代表这个账号授权的一份浏览器安装。沿用短时配对请求与一次兑换的交互，共享网站按账号生成一次性专用配对码，用户在插件或本机设备输入后建立有限期连接。密码只输入网站。插件获得可撤销、范围有限的凭据；网页登录 Cookie、模型 Key 和服务器运维凭据不交给插件。聊天、操作网页、访问项目分别授权。
- **本机连接**由执行端主动连到共享网站，不开放用户电脑的入站端口。真实路径保留在本机，网站使用设备 ID、项目 ID 和显示名。后端派发前、本机执行前分别核对账号、设备、项目及权限。项目默认只读，写入和命令沿用逐次审批；撤销设备后拒绝新任务，已派发且无法确认结果的写操作不自动重放。按任务读取的文件片段可能进入网站及模型上下文，不默认上传整个目录。

改密、重置密码或停用账号应撤销该账号已有会话与连接授权；重新启用不恢复旧授权。解绑设备或插件只撤销对应连接。网站记录账号管理、配对、审批与部署事件，不把密码、令牌、对话正文或文件内容写入运维日志。

## 分阶段交付与验收

1. **账号与隔离**：增加独立的共享网站启动入口、持久化账号与会话、管理员账号页、登录退出、改密和重置。先用两个成员和一个管理员验证权限：成员不能管理账号、调用部署接口或通过已知 ID 访问对方资源；禁用后旧会话失效。现有环回端口和本机操作员模式保持原用途。
2. **网站与插件对话**：接入团队模型配置、用户会话和插件配对。用两个浏览器配置文件分别登录不同账号，验证聊天记录互不可见、配对只能兑换一次、解绑后无法继续调用。保留现有插件独立模式；不把本机配对令牌升级成网站凭据。
3. **设备与目录任务**：复用本机 Nexus / Runner，增加账号绑定、设备在线状态及任务领取和回传。用两台设备上的同名目录测试：任务只到指定设备，读写范围不越界，离线、撤销、拒绝及中断都能看到真实结果。
4. **共享部署与运维**：迁入管理员专用部署配置，区分服务器运维目标和成员设备；实测 HTTPS、备份恢复、管理员更新 Compose 应用及失败处理后，再发布多人站点。

当前工作台的操作员会话不代表个人账号，项目列表来自本机 Nexus，模型配置和部署目标也是工作台级资源。因此不能只修改监听地址、加反向代理或替换登录表单就宣称支持多人。迁移不自动导入个人目录、历史会话、SSH 密钥或本机模型凭据。
