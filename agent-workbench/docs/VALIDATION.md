# Navi 验收

本文件记录历史验收结果。文中的脚本名和命令用于标识当时的验证项目，不是当前可运行的入口。

验收环境为 macOS arm64、Node.js 24.18.1 和 Docker Chromium。除明确标为真实模型的项目外，模型响应和业务数据使用合成夹具。

## 团队网站、成员权限与文件共享

团队网站专项 11 项及部署模块 16 项在本机通过。SQLite 文件、用户口令的 scrypt 派生、会话及站点正式路由参与测试。两个成员与管理员验证了跨账号隔离；二进制任务文件覆盖默认私有、指定账号可读/可编辑、并发版本冲突、不允许接收方再授权或删除、撤销后拒绝下载与更新。已验证将共享文本的指定版本提交到接收方的目录任务，以及将任务结果另存为私有文件。还验证了空库初始化、拒绝重复初始化及数据库 0600。

模型、设备及部署执行链使用夹具；没有向实际设备下发任务或调用线上模型。本轮工作台标准回归 213/278 通过，65 项受本机监听权限和浏览器夹具影响；其中 57 项另以内存 HTTP 传输通过。扩展 211/211、套件前端与 UI 测试 70/70 通过。以上为受限环境的结果；同日在允许回环监听的宿主机运行 `npm run test:all`，569 项中 568 项通过、0 项未通过、1 项因 17880 端口被运行中的 Navi 占用而跳过，扩展独立模式和 Chrome 原生侧栏的真实 Chromium 脚本也通过。真实端到端与夹具结果见[最新功能测试报告](../../outputs/功能测试报告-2026-11-17.md)。尚未上线公网、验收 HTTPS 代理或完成双机联调。[操作与复验步骤](TEAM_SITE.md)。

## 独立扩展模式

`test:browser:direct` 在禁用外网的隔离容器中加载真实 Chromium 扩展，没有启动 Navi 或 MCP 服务。已通过首次保存模型 API、两轮历史对话、百度搜索标签页、页面读取/填写/点击、拒绝、停止、重新打开恢复、可选本机工具提示、公开配置不含凭据、模型名称显示和 360px 布局检查；监测未出现 17880/18080 服务请求。Chrome 原生 360px 侧栏还通过模型设置默认关闭和输入区可见性检查。

独立和本机模式都在真实 Chromium 中验证了“打开百度网站搜索苹果”：一次确认、新增一个标签页，不读取结果，四个阶段默认不可见；点击操作记录图标后可展开查看。六步网页任务同样只显示一个记录入口。网站和模型为合成夹具。

界面回归还检查输入框与 28px 文件夹／发送图标同排、提示独立一行、底部模型菜单、360px／750px 设置弹窗、Esc 关闭和草稿保留。合成模型声明强度能力时显示菜单，切到无能力模型时隐藏；请求体检查确认所选 `reasoning.effort` 实际传入，运行恢复保留所选强度，未声明的强度被拒绝。

此项使用合成 Responses 服务和 HTTPS 网页夹具，测试副本预授予夹具站点权限；不等于已经验证真实线上模型、线上百度结果或原生权限弹窗。此前真实 `gpt-6-luna` 验收属于本机模式，不能替代独立模式的真实模型验收。原有网页工具及本机配对模式的浏览器回归均通过。

本次使用工作台已保存的真实模型连接，发送“通过现有浏览器打开百度网站搜索苹果图片”及正式 `navi_browser` 定义，实际返回了 `function_call`（`search`，查询词“苹果图片”）。该探测没有执行页面操作。随后通过 Chrome 原生无障碍界面确认用户截图中的实际连接为“使用本机 Navi”，只显示项目用例测试授权，未授权浏览器与本机文件操作；这解释了该轮没有浏览器工具。新版扩展已在用户 Chrome 中重新加载，授权页已打开。真实模型在增加 `tool_choice` 后同样返回了 `navi_browser` 调用。

## 日常浏览器与目录操作的验证范围

`test:browser:automation` 使用真实 Chromium、正式扩展后台和正式 RunManager，通过对话确认后创建百度搜索标签页（查询词为“苹果”）、读取网页、填写输入框、点击并读回结果。还覆盖快速工具返回后的批准按钮恢复、拒绝不打开标签页、停止不派发，以及 440px 侧栏视图。侧栏顶部不显示项目；文件任务先在对话中选择再继续，新对话清除选择，网页任务无须选项目。发送和停止图标保留无障碍名称；旧后端缺少能力声明时侧栏阻止发送并提示真正重启服务。模型、Nexus 和网页内容均为合成夹具；夹具页面由容器内 HTTPS 服务提供，容器禁用外网。测试副本预授予夹具站点权限，尚未验收 Chrome 原生站点授权弹窗。

Finder 路由的调用链、真实文件系统路径校验和固定启动参数已测试，包括目录不存在、文件冒充目录、不同 Runner 和符号链接越界。对话浏览器集成中的 Finder 使用模拟适配；本次宿主沙箱不能启动 Finder（LaunchServices 返回 `kLSNoExecutableErr`），不计为实际桌面打开成功。新功能尚未完成“线上模型 + 用户 Chrome + Finder”的整体实测，也不包含全桌面 Computer Use。

## 浏览器与本机文件权限拆分

授权页的两个操作开关默认关闭，分别记录 `browserAutomation` 和 `fileOperations`。四种组合的单测覆盖工具目录、伪造目录／网页调用被拒绝、写入工具范围、审批与浏览器领取边界。HTTP 配对与上下文回查验证浏览器单独授权不会开放文件写入，文件单独授权不会开放日常浏览器操作；原有项目只读和独立用例测试授权不变。旧合并字段与新字段混用会被拒绝。

工作台 231 项、扩展 131 项单测通过；真实 Chromium 的扩展操作回归验证拆分授权标签、只授权浏览器仍能操作网页，以及未授权网页操作时的发送前提示。授权页面提供 `splitAutomation` 能力声明；旧后台不能使用新的拆分授权页，会明确提示重启。

宿主仍运行旧工作台。尝试向已确认的 Navi 后台进程发送 SIGTERM 被本机沙箱以 `operation not permitted` 拒绝；未绕过限制，也未替用户启用合并权限。代码和安装包已更新，实际宿主生效需要用户重启工作台、重新加载扩展并重新配对。
